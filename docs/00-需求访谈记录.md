## 0. 背景与目标

- 目标：把**智联招聘 Web**（登录域 `passport.zhaopin.com`，数据域 `www.zhaopin.com`）封装成一个**本机常驻的只读客户端**，复用 `~/cloak-env` 的 cloakbrowser 运行环境，但使用**独立 profile**；对外提供 **CLI / REST / MCP / SKILL** 四种形态，供 Agent 与其他业务系统调用。
- 参照物：同机已有 `boss-client`（BOSS直聘本地客户端，架构与工程约定成熟），本项目做**同构复制改造**，差异只在「智联招聘」的站点适配（登录链路、EdgeOne 人机验证、SSR 数据结构）。
- 数据用途：与 boss-client 相同——按岗位关键词（如「外贸」「国际贸易」「海外销售」）找到**正在招这类岗位的公司**，结合公司详情/工商信息形成销售线索；**只读**，不投递、不沟通、不改简历、不写 CRM。
- 用户最初系统设想图（简版）：

```text
┌─ 本机 ────────────────────────────────┐
│  ┌─ zhilian client ─────────────────┐ │
│  │  cloak browser session           │ │
│  │        ↓                         │ │
│  │  local cache                     │ │
│  └──────────────────────────────────┘ │
│      ↑↓ name search / company list    │
│      ↑↓ company detail   ↓ check status ↑ status
│  ┌─ MCP / CLI / REST ───────────────┐ │
│  └──────────────────────────────────┘ │
│            ↓                          │
│  ┌─ SKILL ──────────────────────────┐ │
│  └──────────────────────────────────┘ │
└───────────────────────────────────────┘
```

## 2. Round 2（探路实测，2026-11-14）

> 详细请求/响应、截图、state 样本见 [实测记录](../exploration/2026-11-14/REPORT.md) 与 `exploration/2026-11-14/artifacts/`。
> 环境：cloakbrowser 0.6.5 + Chromium 146，headful，独立 profile `~/.zhilian-client/profile`，真实匿名会话；登录部分待人工扫码。

| 主题 | 实测结论 |
| --- | --- |
| 登录页 | `https://passport.zhaopin.com/login`；登录面板由 knobout + widget（`zp-passport-cust-v2`）渲染，默认面板 `register-sms-1`（手机号 + 短信验证码） |
| 智联APP扫码 | `GET /v4/appScan/init?scene=10000060` → 二维码 `/v4/appScan/img/<id>`（300×300 JPEG）→ 轮询 `GET /v4/appScan/login?validateId=&rememberMe=true`（2s；102004 待扫 / 102001 已扫待确认 / 100000 成功 / 102002-3 失效）；QR 约 5 分钟有效 |
| 其他登录 | 短信（`/v4/sms/init`、`/v4/sms/login(AndRegister)`，可能阿里 NC/极验 v4）；密码（`/v4/account/loginV2` + RSA 加密）；微信扫码；QQ/微博 |
| 登录态检测 | `GET https://fe-api.zhaopin.com/c/i/checkToken` → 未登录 `{"code":200,"data":false}`；登录后 `data=true`（待复验）；`/c/i/user/detail` 登录后返回用户信息 |
| 匿名限制 | 职位搜索匿名只给 **1 页 20 条**（`hasMore=false`），薪资页面展示 `**-**元`（但 SSR state 有真值）；登录后解锁分页与招聘者等字段（待复验） |
| 职位搜索 | `https://www.zhaopin.com/jobs/?kw=<词>&jl=<城市码>&p=<页码>&order=<排序>`；Vue SSR，HTML 内嵌 `__INITIAL_STATE__`（`positionList` 20 条 + `jobDetail` + `baseData` 城市树等）；无独立列表 XHR |
| 城市码 | `jl` = 城市码：489=全国、530=北京、565=石家庄、765=深圳、763=广州、653=杭州、801=成都、736=武汉、635=南京、854=西安…；完整注册表见 `artifacts/city-registry.json`（34 省 / 457 城市 / 2870 区县） |
| 职位详情 | 页面 `/jobdetail/<positionNumber>.htm`（SSR + EdgeOne）；**独立 API** `GET https://fe-api.zhaopin.com/c/i/jobs/position-detailv3?number=<positionNumber>&identity=0` 返回完整 `detailedCompany/detailedPosition`（免 EdgeOne） |
| 公司详情 | `/companydetail/<companyNumber>.htm`；SSR state 含 `companyDetail.companyBase` + `businessInformationData`（工商信息）+ 在招职位入口 |
| 公司全部职位 | `/companydetail/jobs-<companyNumber>/`；SSR state `onlinePositions[]`（实测 12 条全量）+ 筛选条件 + `serverJobDetail` |
| 反爬/风控 | **腾讯云 EdgeOne** 人机验证（`/jobdetail` 首次直访被拦，勾选「确认您是真人」通过，写 `EO-Bot-Captcha-Token`，**30 天**）、数美设备指纹（`reportShuMeiDevice`）、阿里 NC、极验 v4、Sensors/百度/Sentry 埋点 |
| EdgeOne 通过方式 | headful 下点击 iframe `#tcaptcha_iframe_eo` 内 `#verifyCheckbox`，约 5s 后 token 生效并重载；可自动化，也可人工/REST 中继 |
| 请求量特征 | 页面加载伴随大量辅助 XHR（base data、user-city、footer、qrcode、experiment、埋点）；**客户端应改为「页面内 fetch 文档 + 解析 SSR state」而非每一次都加载完整页面** |

## 3. Round 2 后的设计决策（实现方确定）

| 决策 | 结论 | 理由 |
| --- | --- | --- |
| 项目命名 | `zhilian-client`；CLI `zhilian`；MCP 前缀 `zhilian_`；MCP server `zhilian-client` | 与既有 `boss-client`/`tanji-client` 命名一致 |
| REST 端口 | `127.0.0.1:8791` | boss 占 8790、tanji 占 8787-8789，8791 空闲 |
| 数据目录 | `~/.zhilian-client`（profile/cache/logs/run/session.json） | 与 boss/tanji 完全隔离，避免单实例/profile 冲突 |
| 环境变量前缀 | `ZHILIAN_` | 与 boss 的 `BOSS_` 对齐 |
| systemd | `zhilian-client.service` | 同构 |
| 默认城市 | 石家庄 `565`（可配多城市） | 与 boss-client 默认城市一致，贴近实际业务 |
| 默认登录 | 智联APP扫码（headless 可跑）；短信为备选 | 实测扫码链路纯 HTTP 可中继，短信需验证码中继 |
| 匿名/登录双模式 | 匿名可用（1 页 20 条）；登录后解锁分页；`status` 明示模式与限制 | 用户要求只读与稳定，登录前即可开始查询 |
| EdgeOne 策略 | 登录/只读操作遇到 EdgeOne → 返回 `HUMAN_VERIFICATION_REQUIRED` + 截图/iframe 信息；支持「自动点击」与「人工/REST 中继」两种解法；token 30 天内复用 | 30 天 token 使人工介入成本极低 |
| 缓存 TTL | query 24h / 职位列表 2h / 职位详情 12h / 公司详情 7d / 公司全部职位 2h | 沿用 boss-client 默认，可配 |
| 限频 | 上游单并发；15 次/分；页间 2.5–4s 抖动；单任务 ≤5 页；`maxPages` 可配 | 智联风控严格，保守策略 |
| 采集方式 | 页面内 `fetch` 文档 HTML + 解析 `__INITIAL_STATE__`；详情优先 `position-detailv3` API；仅必要时导航页面 | 显著降低请求数与风控暴露面 |
| GitHub | `zhilian-client` 仓库（复制 boss-client 骨架改造，MIT 许可保留版权声明），文档先行推送 | 用户明确要求 |

## 4. 与 boss-client 的关键差异

| 维度 | boss-client | zhilian-client |
| --- | --- | --- |
| 登录入口 | `www.zhipin.com/web/user/`（BOSS App 扫码 + 短信 + 极验） | `passport.zhaopin.com/login`（智联招聘 App 扫码 + 短信 + 阿里 NC/极验 v4 + 微信/密码备选） |
| 人机验证 | 极验 v3（登录时） | **EdgeOne（页面级，30 天 token）** + 阿里 NC/极验 v4（登录时） |
| 数据来源 | wapi JSON API + 公司页 SSR DOM | SSR HTML `__INITIAL_STATE__` + `position-detailv3` API |
| 搜索匿名 | 未登录访问通常要求登录 | **匿名可搜 1 页 20 条**（降级模式） |
| 公司 ID | `encryptBrandId` | `companyNumber`（`CZL…`/`CZ…`/`CC…`/USCC 形态） |
| 职位 ID | `encryptJobId` | `positionNumber`（`CCL…J…`） |
| 城市码 | `cityCode`（如 101090100） | `jl`（489=全国、565=石家庄…） |
| 分页 | `page/pageSize` API | SSR `p` 参数；登录后解锁，匿名 1 页 |
| 公司职位页 | `/gongsi/job/<id>.html` | `/companydetail/jobs-<companyNumber>/` |

## 7. Round 3（登录/会话实测，2026-11-14 20:03）

> 用真实账号（求职者）完成短信验证码登录；本节结论已同步进 PRD/接口草案/部署/环境文档与 [实测记录](../exploration/2026-11-14/REPORT.md) §16。

| 主题 | 实测结论 |
| --- | --- |
| 短信登录 | `getEncryptKey` → `passportService/verify/init`（本次极验自动通过）→ `v4/sms/init`（validateData=geetest JSON）→ `v4/sms/loginAndRegister`（validateData=短信码，`rememberMe=true&agreementConsented=true`）→ 跳 `www.zhaopin.com/recommend` |
| 登录态 | `checkToken` → `{code:200,data:true}`；`user/detail` 返回 userId/姓名/resumeNumber；passport 的 `napi/userinfo` 从 www 页面调用仍 500，不作判定依据 |
| 会话 token | `at`（access token，≈7 天）+ `rt`（refresh token，≈30 天），`.zhaopin.com`、非 HttpOnly、SameSite=Lax；fe-api 用 query `at/rt` 或头 `x-zp-at/x-zp-rt` 传递 |
| 刷新 | `POST https://fe-api.zhaopin.com/c/i/refresh-token` body `{"rt":"<rt>"}` → `{at,atExpire,rt,rtExpire,userInfo}`；at 有效时返回同一 token，推测临近过期签发新 token（待长期观察） |
| 自动登录 | 关闭浏览器/重启进程后同 profile 直接已登录（无需重扫） |
| 搜索分页 | 第 1 页 SSR；第 2 页起 `POST /c/i/search/positions`（body 含 pageIndex/S_SOU_FULL_INDEX/S_SOU_WORK_CITY/at/rt/cvNumber/resumeNumber/sortType）；返回 `data.list/isEndPage/count/sortTypes`；`sortTypes` 为 DEFAULT/HR_ACTIVE_TIME/JOB_PUBLISH_TIME |
| 登录后差异 | 搜索 `hasMore=true` 可翻页；薪资正常显示（匿名 `**-**元`）；招聘者 `staff` 更全；`/jobdetail` 仍可能触发 EdgeOne（再次点击通过） |
| 公司全部职位 | SSR 首页只有 20 条、`?p=2` 未生效；已实现走 fe-api `/c/i/company/search-position` 分页拉全量（>20 条也完整） |

### Round 3 后的新增决策

| 决策 | 结论 |
| --- | --- |
| 会话策略 | 以 `rt`（30 天）为长期凭证；`status` 心跳 `checkToken`；at 剩余 <1h 时调 `refresh-token` 并回写 cookie；rt 过期 → `needs_human` |
| 认证/脱敏 | `at/rt`、短信码、手机号、姓名、userId 一律不写日志/不入库/不贴聊天；`status` 只返回脱敏账号与到期时间 |
| 搜索翻页实现 | 封装为「第 1 页 SSR + 第 2 页起 load-more API」，对上层仍是 `page` 语义 |
| 公司职位全量 | 平台优先走 fe-api 公司职位分页接口（pageSize=100，循环至 count/isEndPage）拉全量，SSR 仅回退；`truncated` 只在未取全时出现 |
| EdgeOne 可重复 | `verification.*` 支持任意时刻再次触发/再次求解（登录后也会出现） |
