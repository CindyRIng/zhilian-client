# zhilian-client 环境配套

> 本文说明 `zhilian-client` 依赖的共享 cloak 环境、Node/FHS、独立 profile、智联登录态 cookie、DISPLAY/Xvfb、权限与版本约束。
> 部署与日常使用见 [03-部署与使用.md](./03-部署与使用.md)。

---

## 1. 组件关系

```text
~/cloak-env/                       共享环境（项目外部，多客户端共用）
├── fhs.nix                        FHS 构建表达式
├── cloak-fhs -> /nix/store/...    FHS 根（GC root）
├── package.json                   cloakbrowser 0.6.5 + playwright-core 1.65.0
├── node_modules/
├── bin/cloak-run                  进入 FHS 后执行命令
└── bin/cloak-env-info             版本/路径信息

~/zhilian-client/                  本项目（代码与配置）
├── bin/zhilian-run                通过 cloak-run 运行 dist/main.js
├── dist/                          tsc 产物
├── spec/                          生成物（openapi / mcp-tools / schemas / operations）
├── systemd/zhilian-client.service  systemd user unit
├── skills/zhilian/SKILL.md        SKILL
└── .env                           本项目配置（600）

~/.zhilian-client/                 本项目运行时数据（独立于 boss/tanji）
├── profile/                       Chromium userDataDir（登录态）
├── cache.db                       SQLite 结构化缓存
├── logs/zhilian.log               JSONL 日志
├── run/zhilian.lock               单实例锁
└── session.json                   storage state（可选，600）
```

| 位置 | 职责 | 谁写 | 可否删除 |
| --- | --- | --- | --- |
| `~/cloak-env` | 共享 FHS + 浏览器二进制 + npm 包，供 boss/tanji/zhilian 共用 | 人工维护（nix build / npm install） | 会破坏所有客户端，勿删 |
| `~/zhilian-client` | 本项目代码、配置、unit、SKILL | git / npm / 手工 | 重装即可恢复（`.env` 需备份） |
| `~/.zhilian-client` | 登录态、缓存、日志、锁 | 运行时自动 | 可删，代价见 §5 |

**关键原则**：FHS 与浏览器二进制共享，**profile 必须每个项目独立**。`~/.zhilian-client/profile` 不与 `~/.boss-client/profile`、`~/.tanji-client/profile` 或 fuma 的 `browser-profiles/*` 共用。

## 3. 为什么需要 FHS

NixOS 默认没有 FHS 的 `/lib64/ld-linux-x86-64.so.2` 等路径，而 cloakbrowser 的 Chromium 是通用 Linux 二进制，直接在 NixOS 主环境启动会缺动态库。`~/cloak-env/fhs.nix` 构建一个 FHS 兼容根，`bin/cloak-run` 进入该根后再执行 Node/Chromium。

因此：

- **项目运行**：`bin/zhilian-run` → `~/cloak-env/bin/cloak-run node dist/main.js`（`CLOAK_ENV` 可覆盖共享环境路径）。
- **开发/测试**：`npm run build` / `npm test` 不启动浏览器，可在主环境跑。
- **只有启动浏览器**（`status`/`login`/`search`/`detail`）才需要 cloak-run；纯 `health`/`docs` 可 `node dist/main.js` 直跑。

`cloak-run` 的三个环境变量：

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `CLOAK_ENV` | `~/cloak-env` | 共享环境根（`bin/zhilian-run` 使用） |
| `CLOAK_FHS` | `$CLOAK_ENV/cloak-fhs` | FHS 根；指向错误会导致 `FHS not found` |
| `CLOAK_WORKDIR` | 当前目录 | 进入 FHS 后的工作目录（`zhilian-run` 已 `cd` 到项目根） |

> `cloak-run` 在未设置 `DISPLAY` 时会默认 `DISPLAY=:0`；无桌面服务器必须显式提供 Xvfb 的 `:99`（见 §6）。

## 4. 安装 / 检查 cloak-env

若本机已有 `~/cloak-env`，只需检查版本与 FHS 路径（§2）。若缺失或损坏，重建 FHS：

```bash
cd ~/cloak-env
NIXPKGS_ALLOW_UNFREE=1 nix build --impure --expr 'import ~/cloak-env/fhs.nix' -o ~/cloak-env/cloak-fhs
~/cloak-env/bin/cloak-env-info
```

- `-o` 建立 GC root，避免 `nix-collect-garbage` 后 `cloak-fhs` 指向失效路径。
- Chromium 首次启动会自动下载到 `~/.cloakbrowser`（约 200MB），需要网络；下载失败会表现为「浏览器启动即退出」。
- 项目侧只锁版本，不复制环境：`package.json` 精确锁定 `cloakbrowser: 0.6.5`、`playwright-core: 1.65.0`。

使用其他位置的共享环境：

```bash
CLOAK_ENV=/opt/cloak-env zhilian status
# 或长期写入 .env（非 ZHILIAN_ 前缀，cloak-run 直接读取）
```

## 5. profile 与登录态

### 5.1 独立 profile

- 默认：`~/.zhilian-client/profile`（`ZHILIAN_PROFILE_DIR` 可改）。
- 通过 `launchPersistentContext({ userDataDir })` 持有；智联登录 cookie、localStorage、设备指纹都在其中。
- 一个 profile 同一时刻只能被一个 Chromium 进程占用 → 这是 `ALREADY_RUNNING` / profile 锁的根因，也是 MCP 默认代理到常驻服务的原因。
- 删除 profile 只丢登录态与 EdgeOne token，不影响 `cache.db`。

### 5.2 智联登录相关 cookie

实测（2026-11-14，匿名 + 登录页链路）观察到的关键 cookie；仅记录 name/domain/有效期，不记录 value：

| cookie | domain | 有效期 | 作用 | 丢失后果 |
| --- | --- | --- | --- | --- |
| `EO-Bot-Captcha-Token` | `.zhaopin.com` | **30 天**（实测至 2026-12-14） | 腾讯云 EdgeOne 人机验证通过凭证 | `/jobdetail` 直访重新挑战；`position-detailv3` 不受影响 |
| `FSSBBIl1UgzbN7NS` | `www.zhaopin.com` | 约 1 年（HttpOnly+Secure） | 数美设备指纹 | 重新生成；对风控评分的影响**待实测确认** |
| `x-zp-client-id` | `.zhaopin.com` | 约 1 年 | 设备 ID，随请求头/参数携带 | 变成「新设备」，可能更容易触发验证 |
| `x-zp-device-sn` | `.zhaopin.com` | 约 1 天 | 短期设备序列号 | 自动刷新，无需处理 |
| `LastCity` / `LastCity_id` | `.zhaopin.com` | — | 上次浏览城市，影响默认 `jl` | 回落到 IP 城市或 `ZHILIAN_CITIES` |
| 登录会话 cookie | 待实测确认 | 待实测确认 | 登录态凭证（`checkToken` 为 true 的依据） | 需重新扫码 |

> 登录成功后的完整 cookie 清单、localStorage token 键名、`rememberMe=true` 是否延长会话，探路报告 §9 仍为 PENDING，**待实测确认**。

### 5.3 备份 / 清理

```bash
# 备份登录态（停服务后再复制；含敏感信息，600 保存）
systemctl --user stop zhilian-client
tar -czf ~/zhilian-profile-$(date +%F).tar.gz -C ~ .zhilian-client/profile .zhilian-client/session.json
systemctl --user start zhilian-client

# 清理登录态，保留缓存
systemctl --user stop zhilian-client
rm -rf ~/.zhilian-client/profile ~/.zhilian-client/session.json
zhilian login --qr
```

- 备份内含登录 cookie 与设备指纹，等同账号凭证：不要入库、不要贴聊天、不要放共享盘。
- 只清 `cache.db` 不影响登录；只清 `profile` 不影响缓存。

## 6. DISPLAY / Xvfb

| 场景 | 是否需要 headful |
| --- | --- |
| 智联 APP 扫码登录（默认） | 否，headless 可渲染/导出 Base64 二维码 |
| 短信验证码登录 | 是（页面交互 + NC/极验） |
| EdgeOne 自动点击（`ZHILIAN_EDGE_AUTO=true`） | 是（需真实渲染与鼠标事件） |
| 只读查询（搜索/详情/公司） | 否，token 已在 profile 中时 headless 即可 |

- 桌面环境：`DISPLAY=:0`（Wayland 下走 XWayland）。
- 无桌面服务器：Xvfb。

```bash
Xvfb :99 -screen 0 1440x900x24 &
export DISPLAY=:99
ZHILIAN_HEADLESS=false zhilian login --sms
```

systemd user unit 内：

```ini
Environment=DISPLAY=:99
ExecStartPre=/usr/bin/Xvfb :99 -screen 0 1440x900x24
```

建议流程：**headful 完成一次登录 + 过一次 EdgeOne**，之后 `ZHILIAN_HEADLESS=true` 只读；token 过期（30 天）或掉线时再临时 headful。若完全无法提供 DISPLAY，用 `zhilian login --relay` + REST 中继（03 §5.3/5.4）由人工完成。

检查：

```bash
stat -c '%a %U %n' ~/.zhilian-client ~/.zhilian-client/profile ~/.zhilian-client/cache.db
```

`bin/zhilian-run` 会 `cd` 到项目根；`.env` 由进程启动时加载（不覆盖已 export 的变量），因此 `systemd` 用 `EnvironmentFile=` 与 `.env` 是同一份配置。

## 8. 版本升级策略

- **不要把 cloakbrowser 升到 0.7.x**：需要 license key；本项目与 cloak-env 一起锁 0.6.5。
- 升级 cloakbrowser：先改 `~/cloak-env`（`npm install cloakbrowser@<ver> --save-exact`），再同步本项目 `package.json` 精确版本，跑 `npm test` + 一次 `zhilian status` 冒烟。
- 升级 FHS/Chromium 后重新 `~/cloak-env/bin/cloak-env-info`，确认 `cloak-fhs` 路径有效（重建会换 Nix store 路径）。
- 项目依赖升级：`npm install` 后 `npm run build && npm test && npm run gen:check`；`build` 内含 tsc 类型检查。
- 智联改版（EdgeOne 模板、`__INITIAL_STATE__`、`position-detailv3` 字段）不需要动 FHS，只更新 `adapters/zhilian` 与 fixtures。

## 9. 常见问题

| 问题 | 原因 / 处理 |
| --- | --- |
| `cloak-run: FHS not found` | `~/cloak-env/cloak-fhs` 不存在或被 GC；按 §4 重建 |
| `Cannot find package 'cloakbrowser'` | 不在 FHS 内或 node_modules 缺失；用 `bin/zhilian-run`，并 `npm install` |
| `HEADFUL_REQUIRED` | 短信登录 / EdgeOne 自动点击需要 DISPLAY；扫码登录不需要；用桌面、Xvfb 或 `--relay` |
| profile 被锁 / `ALREADY_RUNNING` | 另一个 zhilian 进程占用 `userDataDir`；`pgrep -af zhilian`；停 systemd 服务；确认无进程后删 `run/zhilian.lock` |
| 浏览器启动即退出 | 检查 Chromium 二进制（`~/.cloakbrowser`）、FHS、`DISPLAY`；先跑 `cloak-env-info` |
| EdgeOne 反复验证 | headless 下自动点击通常无效；headful 过一次让 `EO-Bot-Captcha-Token` 落盘；并校准系统时间 |
| 缓存降级 memory | `ZHILIAN_CACHE_DRIVER=memory` 时重启即丢缓存，仅用于排障/SQLite 修复期 |
| `node:sqlite` warning | Node 22 实验特性提示，不影响功能 |
| Chromium 首次启动很慢 | 正在下载到 `~/.cloakbrowser`（约 200MB），需网络 |
| `DISPLAY` 未设置导致 headful 失败 | `cloak-run` 默认 `:0`；Xvfb 场景需显式 `export DISPLAY=:99` |

## 10. MCP 与常驻服务

`zhilian mcp` 默认是 **REST 代理**，不创建本地 App、不持有浏览器/profile；通过 `ZHILIAN_CLIENT_URL`（缺省 `http://127.0.0.1:8791`）调用常驻服务。只有显式 `zhilian mcp --local` 才会本地启动浏览器，常驻服务运行时必然 `ALREADY_RUNNING`。

```bash
systemctl --user status zhilian-client        # 先确认 active
curl -s http://127.0.0.1:8791/v1/health       # 免鉴权探活
```

因此：**一个 profile 只由一个进程持有** —— systemd 服务持有浏览器，CLI（设置了 `ZHILIAN_CLIENT_URL`）与 MCP 都只走 REST。

## 12. 待实测确认
